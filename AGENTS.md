# AGENTS.md · OpenFlightClaims

## Project identity

Static-first Next.js App Router directory of official airline claim/refund/complaint links. No database, auth, CMS, admin panel, AI chatbot, analytics SDKs, or required env vars. Deployed on Vercel.

See `CODEX.md` for the full working brief (data model, verification rules, UI direction, scope boundaries).

## Commands

```bash
npm run dev              # start dev server
npm run typecheck        # tsc --noEmit
npm run lint             # eslint .
npm run test             # vitest run
npm run validate:data    # validates data/airlines.json against the airline schema
npm run validate:translations  # validates message files
npm run verify:links     # writes reports/link-verification.json; does NOT fail on network errors
npm run verify:links -- --write  # same but auto-applies conservative status changes
npm run stamp:verified -- --dry-run   # preview maintainer verification stamps
npm run stamp:verified                # apply verification stamps
npm run stamp:verified -- --by=maintainer  # stamp as direct maintainer
npm run discover:airlines  # runs candidate airline discovery scanner
npm run build             # next build (must pass before deploy)
npm run ci                # full pipeline: typecheck → lint → validate:data → validate:translations → test → verify:links → build
```

## Architecture notes

- **No `src/` directory.** Source lives at root in `app/`, `components/`, `lib/`, `types/`, `scripts/`.
- **`@/*` alias** maps to `./` (project root), not `./src/`. So `@/lib/airlines` resolves to `lib/airlines.ts`.
- **Scripts run with `tsx`** (not `ts-node`). They import from `../../types/airline` (relative), not `@/`.
- **Data is canonical JSON:** `data/airlines.json` is the single source of truth for all airline records. Everything else is derived.
- **All locales are statically generated.** `dynamicParams = false` in `app/[locale]/layout.tsx`. Locales: `en`, `es`, `fr`, `ar`, `ur`. Root `/` redirects to `/en`.
- **Arabic and Urdu use RTL.** The `<html dir="rtl">` is set per locale. CSS has `[dir="rtl"]` overrides where needed.

## Testing

- **Vitest** with zero-config (no `vitest.config.ts` file). Tests live in `tests/`.
- **Only one test file currently:** `tests/eligibility.test.ts`. It tests `lib/eligibility/` pure logic functions. When touching eligibility or claim-template logic, run `npm run test` and consider adding tests.
- Tests are fast and pure — no DOM, no integration tests, no fixtures.

## Data integrity gotchas

- **Public link statuses** are simplified to `active | reported_broken | unknown`. Internally, `listed` and `verified` both map to `active` publicly. Use `getLinkStatus()` from `types/airline.ts` to derive the public status from the internal `AirlineStatus`.
- **`verified` status requires all three:** `officialSourceUrl`, `verifiedAt`, `verifiedBy`. Missing any one is a validation error.
- **IATA codes must be exactly 2 uppercase alphanumeric chars.** `ICAO` must be exactly 3.
- **Slug format is strict:** lowercase alphanumeric with hyphens only (`/^[a-z0-9]+(?:-[a-z0-9]+)*$/`).
- **Obsolete field names are blocked** by the validator (old status values, old source types, old page field names).
- **Intermediary domains are blocked** from verified records (claims-management companies, social media, link shorteners). See the blacklist in `scripts/lib/airline-records.ts`.

## Design system

- **Pure CSS custom properties + BEM class naming.** No Tailwind, CSS modules, or CSS-in-JS.
- **Design tokens in `tokens.css`.** Theme is "Garden" with a chromatic-rose accent. Light/dark via `data-theme` attribute on `<html>`.
- **Theme flash prevention** via inline `<script>` generated by `lib/theme.ts`. The script sets `data-theme` before paint.
- **Fonts via `next/font/google`:** Cormorant Garamond (display, italic serif) + Source Sans 3 (body). Class names must be passed as `fontClassNames` to `<html>`.
- **Mobile-first** with a single breakpoint at `768px`. Grid converts to single column below that.

## Translation conventions

- **English is the source language.** All message keys must exist in `messages/en.json`.
- **Airline names remain official brand names** — don't translate them. Local aliases go in the `aliases` array.
- **Translation validation checks** that all locale files have the same keys as English (and only those keys).
- **`i18n/locales.ts`** is the canonical locale list. Adding a new locale requires: `i18n/locales.ts`, `messages/{code}.json`, and translation validation.

## CI

Workflow: `.github/workflows/ci.yml`. Runs on push to `main`, all PRs, and weekly Monday cron. Pipeline order matters — lint before tests, tests before build. The link verification report is uploaded as a build artifact.

## Things that look like antipatterns but aren't

- **`scripts/lib/airline-records.ts` uses obfuscated field name strings.** The old field names (`sourcePageUrl`, `importedAt`, `needs_verification`, `seed`, `seed_import`) are intentionally concatenated with string splitting to avoid false-positive grep hits in the data file. Do not "clean up" these — the validator must detect them in incoming PRs.
- **`app/(default)/layout.tsx` and `app/[locale]/layout.tsx` are nearly identical.** The default layout handles the root path (before redirect) with hardcoded English; the locale layout handles actual locale routes. Both are needed.
- **The design system uses BEM classes on native HTML without any component library.** That's intentional — the project avoids heavy UI dependencies.

## AI & data endpoints

- `/api/meta` — project metadata, dataset stats, all endpoints listed
- `/airlines.md` — Markdown directory (route at `app/airlines.md/route.ts`)
- `/airlines/{slug}.md` — single airline Markdown (rewrite in `next.config.ts` → `/api/markdown/airlines/{slug}`)
- `/guides/index.md` — all guides Markdown
- `/contributing.md` — contribution Markdown
- `/llms-full.txt` — full AI access guide
- `/openapi.json` — OpenAPI 3.1 spec
- `/mcp` — JSON-RPC 2.0 MCP endpoint (POST, read-only, 8 tools)
- `/mcp.json` — MCP server manifest
- **`.md` dynamic routes with dots don't work natively in Next.js** — `[slug].md` routes must use a rewrite to an API handler. Static dot routes (e.g., `airlines.md/route.ts`) do work.

## When changing the data schema

Always:
1. Update `types/airline.ts`
2. Update `scripts/lib/airline-records.ts` validation
3. Run `npm run validate:data` to confirm existing data passes
4. Add migration logic if renaming fields (and add the old name to `rejectOldValues`)
